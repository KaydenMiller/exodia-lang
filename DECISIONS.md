## 1. Language Direction
- **Decided** — Statically typed, C#/Rust-flavored. The README is the source of truth; the original grammar was a port of a JS-style tutorial grammar and is being reshaped toward the README.
- **Decided** — Compilation target is LLVM (AOT). This *leans toward* compile-time mechanisms over runtime reflection (a preference, **not a prohibition** — reflection is not banned; see §15).

## 2. Type Naming Tiers
Boundary rule: **lowercase iff the type lowers directly to an LLVM scalar; PascalCase iff library-backed** (representation and/or operations defined in software), even if it "feels" primitive.
- **Decided** — lowercase primitives: `int8..int64`, `uint8..uint64`, `float`, `double`, `bool`, `char`. Each maps directly to an LLVM scalar (`i1`/`i8`../`float`/`double`).
- **Decided** — PascalCase library types: `String`, `Decimal`, `Option`, `Result`, `Field`, and all user types. `String` = `{ptr, i64}` struct; `Decimal` = 128-bit base-10 + software math (no native LLVM decimal). Both "feel primitive" but are library-backed.
- **Decided** — One canonical name per type. No C#-style `int`/`Int32` dual naming.
- **Decided** — Signedness is NOT in LLVM: `int32`/`uint32` both lower to `i32`; the compiler enforces signedness and picks instructions (`sdiv`/`udiv`, `sext`/`zext`, `icmp slt`/`ult`).
- **Decided** — Prelude: core library types (`String`, `Decimal`, `Option`, `Result`, `Field`, common variants) are auto-imported and written unqualified (`String`, not `StandardLibrary::String`). Prelude names are *weak* — an explicit declaration/import of the same name wins.

## 3. Numeric Literals & Typing
- **Decided** — Two lexer categories: `INTEGER`, `FLOAT`. `_` digit separators via a `DIGITS` fragment (`[0-9] ([0-9_]* [0-9])?`, digit required on both ends → no leading/trailing/point-adjacent underscore). Strip `_` before parsing.
- **Decided** — `FLOAT` must be its own shape `[0-9]+ '.' [0-9]+ (exp)?`; wired into `numeric_literal` alongside `INTEGER`.
- **Decided** — Suffixes are **optional**, short form: `i8..i64`, `u8..u64`, `f` (float), `d` (double), `m` (Decimal). Long type names + short suffixes are distinct syntactic roles (suffix only on literals), not dual naming.
- **Decided** — `1.5m` is the exact base-10 `Decimal` literal (lexer captures digits, compiler parses base-10 directly — never via a lossy binary `double`). The one genuinely-justified suffix.
- **Decided** — Literal typing = Go "untyped constant" model: an untyped literal target-types to its annotation/context; otherwise falls back to a **default** (`int32` for integers, `double` for reals). Default is **eager** (decided locally at the literal, not via whole-function inference).
- **Decided** — Range/overflow is a *semantic* check, never a parse error (`x: uint8 = 300` parses; the checker rejects it).

## 4. Conversions
- **Decided** — **No automatic conversions.** A type bridge exists only if a conversion is *declared* (C# user-defined-conversion model, generalized so even primitive widenings are declared conversions).
- **Decided** — Plain assignment/argument (no cast): legal iff types match **or** a defined *implicit* conversion exists. Cast expression: legal iff match **or** implicit **or** *explicit* conversion exists. (An available explicit conversion does not rescue a bare `=`.)
- **Decided** — Implicit conversions do **not** chain (declared pairwise; chaining is hard to debug).
- **Decided** — Multiple applicable conversions → error; must disambiguate with an explicit cast.
- **Decided** — Overload resolution: exact match beats conversion-requiring match; ties among conversions → error.
- **Decided** — Cast syntax: `x as int32` (Rust-style postfix). Chosen over C-style `(int32)x` because postfix avoids the cast-vs-parenthesized parse ambiguity. NOTE: this is Rust's value-converting `as`, not C#'s null-on-fail reference-only `as`.
- **Deferred** — Where a conversion is declared (which participating type owns it) and the coherence/orphan rule. v1 provides compiler built-in implicit widenings for numeric primitives; user-defined conversions come later.

## 5. Null, Absence & Errors
- **Decided** — No null. Absence is `Option<T>` (`Some`/`None`). Must be handled or explicitly opted out (`?`, `unwrap`/`expect`, discard) — `must_use`-style enforcement.
- **Decided** — Recoverable failure → `Result<T, E>` (`Ok`/`Err`), must be handled.
- **Decided** — Unrecoverable → **`panic`** (renamed from `throw`), **unchecked** (not part of signatures — avoids Java's checked-exception mistake). "The exception, not the rule." Keyword is **`panic`** not `throw` — deliberately breaks the C/Java/C# muscle-memory of reaching for `throw` by default, and signals it's the unrecoverable escape hatch, separate from `Result`.
- **Decided** — `Option`/`Result`/`Field` are ordinary library *enums* (sum types with payloads) + generics + `match` + exhaustiveness. No compiler magic.
- **Decided — expression-statement discard semantics.** Any expression (incl. `match`) may stand as a statement and have its value **discarded** (Rust model; more permissive than C#, where a bare non-call expression is a CS0201 error). Discarding a **unit/void** value is silent and fine. Discarding a **must-use-typed** value (`Result`/`Option`) is **flagged** (warning/error) and requires an explicit discard (`_ = expr` / `discard`) — this preserves the must-use guarantee above. So a side-effect `match` yielding unit needs nothing; a `match` yielding an ignored `Result` must be opted out explicitly.
- **Decided** — `Field<T> = { Absent, Null, Value(T) }` models the JSON/DB tri-state (present-value / present-null / absent). It is a plain enum; only the serializer/ORM treats `Absent` specially (omit the field / column). Solves C#'s single-`null` limitation for PATCH semantics.
- **Decided — error/absence handling: three separate tools.** (1) **`Result`/`Option` + `?` propagate**, (2) **`throw` + `try`/`catch`/`finally`** for exceptional/panic recovery, (3) **`using`/`await using`** for resource cleanup. There is **no `null`**: control-flow absence = `Option::None` (propagatable); explicit-null-as-data = `Field::Null` (a value you **`match`**, never propagate). Operators: **`?` = safe propagate** (Rust convention: `Ok(x)`/`Some(x)` → unwrap, `Err(e)`/`None` → early-return; enclosing fn must return a compatible type), **`!!` = force-unwrap-or-panic** (Swift/Kotlin `x!`/`x!!` convention — `throw`/panic on `Err`/`None`). Both only apply to **binary try-types** (`Result`, `Option`); **`Field` is always `match`ed** (3 states, no single short-circuit variant — collapsing them defeats its purpose; convert `Field`→`Option` first if propagation is wanted). **`?` is interface-based, NOT compiler magic and NOT any-binary-enum**: it works on types implementing a `Try`/`Propagate` interface (Rust's `Try` trait model — `Result`/`Option` implement it in stdlib; keeps "ordinary enums, no magic"). Grammar of `?`/`!!` is a plain **postfix operator** — **DONE + verified**: `QUESTION: '?'`, `DOUBLE_BANG: '!!'`; `unary_expression → postfix_expression : (primary_expression | call_expression) postfix_op*`, `postfix_op : QUESTION | DOUBLE_BANG`. Parses `f(a)?`, `f(a)!!` as terminal suffixes (tree shows `postfix_op ?` / `postfix_op !!`); backward-compatible (0 postfix ops = old behavior). Known limitation: member access AFTER `?`/`!!` (`getUser(id)?.name`) doesn't parse yet — `.`/`[]` live in `member_expression`, which doesn't wrap `postfix_expression`; unifying the full postfix chain is a deferred refactor. The "which types" semantics + short-circuit→return-type conversion (Rust `FromResidual`; first cut = require exact error-type match) wait on **interfaces** (deferred). **Why `try` is NOT the propagation keyword:** `try`/`catch`/`finally` is reserved for `panic` recovery (need a boundary so one panic doesn't crash the app — cf. Rust `catch_unwind`, Go `recover`, Erlang supervisors), so propagation can't reuse it → `?` it is. **DECIDED: the unchecked-panic keyword is `panic`, not `throw`** — signals separation from `Result` and breaks the C-family default-to-`throw` habit.
- **Deferred** — `try`/`catch`/`finally` (panic recovery boundary; used sparingly, not everyday flow) and **explicit resource management** `using` / `await using` (C# `IDisposable`/`IAsyncDisposable`, TC39/TS 5.2 `Symbol.dispose`/`asyncDispose`). Both have prerequisites: `using` needs a `Disposable`/`AsyncDisposable` **interface** (deferred) and `await using` needs **async/await** (not designed). Alternative rejected: Rust `Drop`/RAII (automatic, implicit) — Kayden prefers the explicit/visible `using` form (consistent with explicit-`return` taste).
- **Deferred** — **`try { }` expression** (Rust-style, opt-in propagation boundary — NOT the panic `try`/`catch` above). Evaluates to `Ok(value)` normally, short-circuits to `Err(e)` if a `?` inside fails; the block, not the function, catches the `?`. This is the scoped/layered propagation Kayden wanted ("`?` up to a boundary, then `?` again to the function") — kept as an explicit construct so it doesn't contaminate `match` arm types (see the `give`/EXIT-vs-PRODUCE decision). NB: naming overlaps with the panic `try` — resolve when both are designed.
- **Decided (model) — user-definable type defaults, Rust `Default` model** (NOT C#'s fixed zero/null, which isn't user-definable). Primitives have **built-in** defaults (`int32`→0, `bool`→false, `double`→0.0, …). User types **opt in** by declaring an **infallible** default (returns `T`, not `Result<T>` — one known-good value). A type with **no** declared default **cannot be defaulted → compile error**; use `Option`/`Field` or pass an explicit value. Because there is no null, a reference-type default is always a real value. Enables `= default` on params and a **target-typed `default` expression** usable wherever the target type is known (`const p: Person = default;`, `return default;`). Two kinds of "optional" are orthogonal and both wanted: **kind 1 = omittable at call site** (default parameter *value*), **kind 2 = may be absent in domain** (`Option`/`Field` *type*). **OPEN:** (a) *declaration mechanism* is coupled to the deferred interfaces/traits decision — near-term a designated `default` member (e.g. static `default(): Self`), long-term a real `Default` interface + optional `derive`-style auto-default from field defaults (needs attributes, also deferred); (b) surface syntax — `= default` target-typed (primary) vs explicit `default(T)`; (c) depends on adding **default parameter values** to grammar first (`formal_parameter : identifier COLON type ('=' assignment_expression)?`), which also unblocks named arguments. Build order: default param values → named args → `default` expr → `Default` interface + derive. Overloads/telescoping constructors are the anti-pattern this avoids; reserve named ctors (`ctor FromCelsius`) for genuinely different construction paths, not optionality.

## 6. Immutability & Mutability
- **Decided** — Type-level immutability (to start): types immutable by default; `mut` opts a field into mutability.
- **Decided** — Bindings: `const` (immutable) / `mut` (mutable); replaced `let`. `const` = immutable *binding* (not a compile-time constant).
- **Decided** — Shallow *and* deep both achievable via type-level: immutable type + `const` binding = deep-locked; type with `mut` fields + `const` binding = shallow. No borrow checker required.
- **Deferred** — Per-binding deep-const on a type that *has* `mut` fields (requires const-correctness or a borrow checker).
- **Decided** — Public-immutable / private-mutable via "option 3": a `private mut` field + a `public` read method (DDD-idiomatic). Asymmetric `private(set)`-style write-visibility is sugar, deferred (capability already exists).

## 7. struct (value objects) & class (entities)
- **Decided** — `struct` = DDD value object: immutable, value equality (compiler-generated), value semantics (copied), stack-allocated → LLVM struct, **no heap/GC**. "To change, create a new one."
- **Decided** — `class` = entity: reference semantics, identity, heap-allocated. Where memory-management complexity lives (deferred).
- **Decided** — `struct` has no inheritance. `class` has `extends` (single base, qualified name). Struct *implementing interfaces* is a possible future.
- **Deferred (grammar)** — `with` expression for non-destructive value-object update (`p with { x: 5 }`), and compiler-generated value equality / value-copy.

## 8. Functions, Methods & Construction
- **Decided** — `fn` keyword for namespace/global-level functions; C#-style methods (no `fn`) inside struct/class bodies. Container-scoped → no field-vs-declaration ambiguity.
- **Decided** — Parameters are always typed (`name: type`). Return type is always declared (mandatory); use `void` when nothing is returned.
- **Decided** — `void` is a real **unit type** (one value), not a C-style non-type — so `Result<void, E>` works uniformly. It is just a type name grammatically. Avoid `none` (collides with `Option::None`). Unit `()` literal deferred until needed.
- **Decided** — Constructors use the `ctor` keyword (chosen over `constructor`). Named + unnamed. No return type. Invoked via `new`, including named form `new Type.Named(...)`.
- **Decided** — Named constructors (Dart-style) adopted for the identical-signature case (`Temperature.FromCelsius`/`FromFahrenheit`, both `(double)`). Invocation reuses member-call syntax, so the cost is one optional identifier on the ctor rule.
- **Decided** — DDD validated construction: **private `ctor` + public `static Create(...): Result<T, E>`** (smart constructor). The private ctor gives the "always valid" guarantee. Needs no new language features.
- **Decided (2026-07-23) — constructor/callable overloading by arity, uniform across all callables.** Revises the earlier lean *against* overloading (which favored named-ctors + default-params only). A struct may declare multiple unnamed ctors (`ctor()`, `ctor(int32)`) and multiple named ctors (`ctor Foo()`, `ctor Foo(int32)`), distinguished by **(name, arity)**. Same keying applies to **functions and methods**, not just ctors — overloading is a uniform capability, keyed `(name, arity)` / `(owner, name, arity)`. **Deferred:** (a) **type-based** overload resolution (same arity, different param types — needs matching arg types to params; arity covers all current cases); (b) the **overloading × default-params ambiguity rule** (§66) — `ctor()` vs `ctor(int32 x = 0)` both answer `new T()`. Codegen note: don't mangle the LLVM name of free functions (breaks `main` as the entry symbol) — rely on the (name, arity) key; LLVM auto-suffixes duplicate symbols and the key selects the right `Fn`.
- **Open (2026-07-23) — implicit `this` for field access (UNDER CONSIDERATION, not adopted).** `this.x` (explicit) is the current direction; a bare `x` resolving to `this.x` (C#/Swift-style, local-shadows-field) is being weighed and **deferred**. Readability feedback (from Kayden's review with peers): explicit `this.x` is more verbose but clearer — it removes ambiguity about whether a name is a field or a local, which is where misreads happen. Revisit deliberately later; do NOT implement the shadowing fallback until decided.

## 9. Dependency Injection
- **Decided** — Compile-time DI (AOT-aligned), built as *tooling* on language primitives — NOT a keyword. **DI must be compile-time checked** — it must NOT resolve services via runtime reflection (the typical C# container model). NB: this bans reflection *as DI's mechanism*, NOT reflection in general (see §15 reflection/metaprogramming — open, not banned).
- **Decided** — Constructor injection is the model; a service's typed `ctor` params are the injection surface (already expressible). DI targets *services* (classes), not value objects. A service depends on the **interface** (interface-typed `ctor` param ⇒ dynamic dispatch), and a **composition root** picks the concrete impl at **runtime** from config — so "compile-time DI" means the wiring graph is verified/generated at compile time (reflection-free), NOT that the provider is frozen at compile time. Many types each implementing one interface once is the normal case (NOT the orphan problem — §15 interface model). Full runtime swappability is retained; the compile-time guarantee is only that nothing is unregistered/miswired (unlike a C# runtime container, where a missing registration fails at runtime).
- **Enablers to add later** — interfaces (the "inversion"), an attribute/metadata system (services, lifetimes), a compile-time codegen/macro hook, generics.

## 10. Module System
- **Decided** — C#-style **declarative namespaces, decoupled from file structure** (explicitly NOT Rust/TS file-path modules). Multiple namespaces per file, nestable, `::`-qualified paths.
- **Consequences** — Needs (a) a way to *enumerate source files* (namespaces don't reveal file locations) — see the tiered discovery model below; (b) a batch, multi-pass front end (parse all → gather symbols by namespace → resolve with imports → type-check), giving order-independence.
- **Accepted trade-off** — Coarser incremental builds (assembly-granularity) vs file-based fine-grained graphs.

**Discovery vs. scoping are separate jobs — keep them separate.** *Discovery* = "which files compile?"; *scoping* = "which names are in scope without the `::` prefix?". The C# `using`-style model splits these (project decides discovery, `using` decides scoping); the TS/Python model fuses them into the path. A fused form like `from "./file.ex" import System::Collections;` was **rejected** — it conflates the two AND fights the namespace/file decoupling (a file path asserts "this namespace lives here," but namespaces span files). Exodia keeps them separate:
- **Scoping — `import`.** Keyword is **`import`** (not `using`). Form `import System::Collections;` brings a namespace's public members into unqualified scope. **Never references a file path.** Because `::`-qualified names already reach everything, `import` is pure ergonomics (skip the prefix), not a capability — the simplest multi-file program (all symbols in the implicit global namespace) needs **no `import` at all**. Optional later: specific-symbol (`import System::Collections::List;`) and alias (`import L = System::Collections::List;`) forms.
- **Discovery — tiered, C#-file-based-apps model (validated precedent: C# file-based apps, .NET 10 / 2025; aligns with Python PEP 723 inline script metadata + Rust single-file packages).**
  1. **script** — `#!/usr/bin/env exodia` shebang + code; discovery = just the entry file. `chmod +x tool.ex; ./tool.ex`.
  2. **multi-file** — add `#:include <glob>` (C# ships `#:include`); discovery = the glob, resolved from the entry file. One line covers a whole directory (`#:include *.ex`).
  3. **project** — a manifest for dependency graphs / multiple outputs; a one-way "graduate" path (cf. `dotnet project convert`) so a growing script becomes a project without reorganizing.
- **`#:` / `#!` directive layer.** Build directives live in the **entry file's header only** (the invoked file); included files are plain source (their `#:` lines ignored/errored) — one config point, no transitive-include chains. Confirmed C# directives to mirror: `#:include` (glob → discovery), `#:package` (deps), `#:sdk`, `#:property`, `#:project`. Lexer/driver: reserve `#!` (shebang, first line only) and `#:` (directives, must precede code) at file top; `#` is otherwise unused (comments are `//`), so the driver reads directives and the lexer skips those lines.
- **Payoff** — scales *down* to one self-contained file and *up* to a project without changing how code is organized; discovery is explicit and self-documenting (no surprise-compiled stray files) yet the whole-dir case is one glob line. This is a **front-end/driver feature** (lexer skip + directive reader + file-set assembly), off the codegen critical path — build it when multi-file lands; methods/interfaces work fully-qualified until then.
- **Open** — (a) glob recursion: single-level `*` vs recursive `**` (and whether globs are relative to the entry file's directory, assumed yes); (b) whether `#` is generally reserved or only `#!`/`#:` at file top; (c) exact manifest format + the graduate path.

## 11. Partial & Nested Types
- **Decided** — `partial class` / `partial struct` supported (generated-code separation; plug-in point for compile-time DI/codegen). Requires `partial` on all parts (explicit opt-in). Type-level modifier (separate from accessibility). Merge is semantic (the gather phase). Grammar cost is one keyword.
- **Decided** — No `partial enum`. **Deferred** — `partial` methods (source-generator feature) until codegen tooling exists.
- **Deferred** — Nested types (types inside types). Namespaces cover scoping; nesting's unique value is *access to the enclosing type's private members*. Grammar-cheap (`member_kind` gains type declarations), resolver-expensive. Revisit for private aggregate helpers.

## 12. Operators & Generics
- **Decided** — Relational split into `LT`/`GT`/`LE`/`GE` tokens (was `RELATIONAL_OPERATOR`).
- **Decided** — Shift `<<`/`>>` implemented in the **parser** as `LT LT`/`GT GT` (a `shift_operator` rule), **not** a lexer `>>` token. This keeps nested generics trivial: `GT GT` in *type* position closes generics; in *expression* position it is a shift — disambiguated by rule context. Symbolic `>>`/`<<` chosen over named (`shl`/`shr`). Precedence: shift sits between relational and additive.
- **Decided** — Generics restricted to **type positions** (covers all current examples), which sidesteps the `<`-vs-comparison ambiguity. `type_arguments` live in the `type` rule; `type_parameters?` on `struct`/`class`/`function`/`method` (optional). Not on constructors or fields. `enum`/interface/type-alias gain `type_parameters` when added.
- **Deferred** — Generic constraints/bounds (`<T: Comparable>`) — needs interfaces first. Expression-position generics (generic calls, `Type<T>::Variant`) — not needed yet.

## 13. Grammar/Parser Mechanics
- Principle: **grammar checks shape; semantics checks meaning** (range, mutability, exhaustiveness, name resolution, conversions).
- Variant *construction* (`Some(5)`, `None`) needs no grammar — it reuses call/identifier syntax; that a name is a variant constructor is resolved semantically.
- Enum variants: tuple payloads (`Some(T)`, `Rect(double, double)`); optional trailing comma; empty enum allowed (semantic warning later).
- `IDENTIFIER` follows C# rules, **full-Unicode (implemented + verified)**: `'@'? IdentifierStart IdentifierPart*` where `IdentifierStart = [\p{L}\p{Nl}] | '_'` and `IdentifierPart = [\p{L}\p{Nl}\p{Mn}\p{Mc}\p{Nd}\p{Pc}\p{Cf}]`. `@` is an optional single leading verbatim prefix (use a keyword as a name, e.g. `@match`), not a repeatable char. `\p{L}` covers Lu/Ll/Lt/Lm/Lo. Verified by parsing `café`, `naïve`, `変数`, `переменная`, `Ⅲ` (Nl as start char), `変数_2`, `@class`, `@match` — all bind as `(identifier …)`. Surrogate-pair (>U+FFFF) chars are ANTLR code-point based so expected to work; not yet tested.
- Ranges (`200..299`) live only in *pattern* position for now, so `..` can also serve Dart-style *cascade* in *expression* position (same token, disambiguated by position). If range *expressions* (`0..10` as a value) are wanted later, switch ranges to `..=`/`..<` (Rust/Swift) to free `..` for cascade.
- Toolchain: ANTLR4, C# target. Parser is regenerated **manually** (Docker `antlr4` alias); no build-time codegen (`Antlr4BuildTasks` declined). Regenerate after every `.g4` edit or the run uses a stale parser.

## 14. Milestone Status
Done: correctness fixes → `qualified_name`/`type` → typed declarations (`const`/`mut`, typed params, mandatory return types) → containers (struct/class: fields, modifiers, `mut`, methods, `ctor`) → namespaces (+ nested, top-level `global fn`) → generics (`type_parameters`/`type_arguments`, nested `Map<String, List<int32>>`) → shift operators → enums (variants, payloads, generics) → **`match`** (expression + statement, destructure/literal/OR/range/`_` patterns, `when` guards) → full-Unicode identifiers → char literals → array literals → C-style `for` (widened condition) + `do-while` `;` → `if`/`else if`/loops (braced + brace-less) → expression-bodied members (`=> expr`) → default parameter values → named arguments → `panic` (diverging expression) → `?`/`!!` postfix operators → `give` (block-arm value) → **interfaces increment 1** (`interface` decl with method signatures; `impl … for …` blocks; both hooked into `statement` + `namespace_member`) → **supertraits** (`interface B extends A, …` — comma-list, reuses `EXTENDS`) → **inline generic bounds** (`type_parameter : identifier (COLON type)?` — single bound per param, `<T: IFoo>`; applies everywhere generics appear; nested-generic bound `<T: IContainer<int32>>` closes as `GT GT`) → **`where` clauses** (`where_clause : WHERE identifier COLON type (',' type)*` — C#-style, **comma-separated** bounds so NO `+`/`ADDITIVE_OPERATOR` clash; `where_clause*` added at all 7 generic sites: fn/method/method-sig/struct/class/enum/impl; composes with inline bounds) → **generic interfaces + access modifiers + associated types** (`interface_declaration` gains `accessability_modifier*` / `type_parameters?` / `interface_outputs?` / `where_clause*`; `interface_outputs : ARROW type_parameter (',' type_parameter)*` — `-> Output` in the HEADER, not the body; `impl_outputs : ARROW type (',' type)*` binds them, `impl Mul<Vector2> -> double for Vector2`; `ARROW: '->'` new token, `in`/`out` reserved for future variance).

**Associated-types design:** outputs are **impl-determined** (vs inputs = caller-chosen), so they get **inference + no param-threading + uniqueness** (`Iterator -> Item`, `for x in it` knows x's type). `->` placed *outside* `<>` so pure-output interfaces need no brackets (`interface Iterator -> Item`) and the single case stays light. Comma-list (no brackets) handles 0/1/many uniformly (`-> Node, Edge`); optionally bounded (`-> Item: IComparable`). Used far beyond operators (iteration, collections, parsers, async, serde-style serializers).

 → **`dyn`** (explicit dynamic dispatch, Rust-route chosen over C#-implicit; `DYN: 'dyn'`, added as an optional prefix on `type` → `DYN? qualified_name type_arguments? ('[' ']')*`, so it works everywhere a type appears: params, returns, fields, array elements `dyn HasArea[]`, generic args `List<dyn HasArea>`. `dyn`-only-on-interfaces + trait-object restrictions are semantic).

**Codegen constraints / deferred:**
- **Literal target-typing NOT implemented.** An un-annotated literal takes its eager default (`int32`/`double`, §3), and inference reads that off `value.TypeOf`. Consequence: an annotation only works when it *matches* the default — `mut x: int32 = 1` is fine, but `mut x: int64 = 1` allocates an `i64` slot and stores an `i32` literal → **type mismatch / invalid IR**. Full Go untyped-constant target-typing (the annotation flows into the literal so `1` is born `i64`) is the next sub-step of the types work; literal suffixes (`1i64`, §42) are the other path.
- **Signedness selection deferred** — everything is signed (`sdiv`, `icmp slt`). `uint*` lowers to the same LLVM type and currently gets signed instructions; correct selection (`udiv`/`ult`) needs the source type carried into codegen (a later semantic layer, §36).
- **`if` empty-merge edge case** — if both arms terminate (both `return`) AND nothing follows the `if`, the `ifcont` block is left with no terminator → invalid IR. The common `if (c) { return x; } return y;` shape is fine (the trailing `return` lands in `ifcont`). Fix = reachability/predecessor check on the merge block, deferred.
- **`const` not enforced immutable** — `const` and `mut` both get a reassignable slot; nothing rejects `const x = 5; x = 6;`. Enforcement = a semantic check tagging each slot's mutability in `_symbols` and rejecting stores to a `const` one, deferred.
- **Forward references — top-level DONE, nested deferred.** `VisitProgram` does two passes: pass 1 `DeclareFunction`s every top-level `function_declaration` (signature → `_functions`), pass 2 emits bodies. So forward calls and mutual recursion resolve at top level (verified: `two-pass.ex` → `7`/`1`/`0`). `DeclareFunction` is idempotent (`ContainsKey` guard), so the second call from inside `VisitFunction_declaration` is a no-op. **Still deferred:** functions nested in `namespace`/`class`/`impl` aren't scanned by pass 1 — extend it to recurse into those containers when they're built.
- **Mixed-type arithmetic needs an explicit cast** — binary/comparison ops dispatch on `left.TypeOf`, so operands must share a type. `1 + 2.5` emits `add i32, double` → invalid IR; write `1 as double + 2.5`. No automatic conversions (§4), so this is by design, but there is no semantic check catching it yet — it surfaces as invalid IR.
- **Logical/unary operand types unchecked** — `&&`/`||` feed `BuildCondBr` (require `i1`), `!` uses `BuildNot` (bitwise complement — logical only for `i1`). Non-`bool` operands produce invalid IR (`condbr i32`) or wrong results (`!5 → -6`). Enforcing `bool` operands is the deferred semantic check.
- **Load/store alignment + no datalayout** — `BuildStore`/`BuildLoad2` don't propagate the `alloca`'s natural alignment (e.g. `i64` slot is `align 8` but its load/store say `align 4`), and the module sets no `target datalayout`. Benign for `lli` (under-aligned access to an over-aligned address is legal), but the datalayout must be set from the target machine before native codegen (`llc`).
- **`print` is bootstrap scaffolding, not the real API** — a magic name special-cased in the call path (not in `_functions`), backed by libc `printf`, one scalar argument only. It's type-unsafe underneath (the format string *is* the type signature; the compiler now generates it from `args[0].TypeOf` so the mismatch class can't recur through this path). The real design is Exodia's own stdlib `print`/`Display`, gated on strings + structs; replace this then.
- **Scalars only** — `MapType` throws on `String`/`Decimal`, structs, arrays (`T[]`), generics (`List<T>`), and `dyn`. Those lowerings come later.

## 15. Deferred / Open
- **Decided** — `match` only, no `switch`. Expression form (subsumes statement use). Arms `pattern (when guard)? => (expr | block)` — guard keyword is **`when`** (C#-style; avoids overloading `if`). Patterns: variant-destructure (`Ok(v)`, `Some(x)`, `None`), literal (`200`), OR (`200 | 201`), range (`200..299`). Guards included (guarded arms don't count toward exhaustiveness → still need a catch-all). Cumulative fall-through deliberately omitted (use explicit conditionals). Exhaustiveness is a semantic check. A bare-identifier pattern is variant / binding, resolved semantically (like Rust). Wildcard is a dedicated `_` alternative in `primary_pattern`; because `_` is now a valid identifier char, ANTLR's string-literal priority makes a bare single `_` tokenize as the wildcard token — so `_` is **reserved** (not usable as an ordinary identifier) while `_foo` / `_1` remain normal identifiers. This matches the C#/Rust discard convention (surveyed: `_` is the de-facto single-slot wildcard across Rust/C#/Swift/F#/Haskell/Scala/Python-`match`/Elixir/Java-21+/Dart; `*` is never a single-slot wildcard — it's rest/splat/glob/import). Single-slot only; **rest-patterns** (ignore remaining fields/elements, e.g. `Rect(_, ..)` or `Point { x, .. }` — Rust overloads `..`, others use `*`/`...`) are deferred until struct/record patterns land. **Built + verified** — parses destructuring, OR, ranges, and `when` guards.
- **Decided — `match`/`if`/loops are block-like statements (no trailing `;`), C/C#/Rust-style.** `if_statement`, `iteration_statement`, `block_statement` were already direct `statement` alternatives (no `;`). `match` was reachable only via `expression_statement : expression SEMI`, forcing a `;`; fix = add `match_expression` as a **direct `statement` alternative**. Exhaustiveness holds in both; "ignore the rest" is written `_ => { }`. Discarding the statement-form's value follows the expression-statement discard rule (see §5: unit silent, must-use flagged). **DONE + verified** — `match_expression` added as a direct `statement` alternative; bare `match e { … }` parses with no `;`, while `const x = match …;` / `return match …;` keep their wrapper `;`. - **Decided — implicit return = C# expression-bodied members; NO Rust block-tail.** A function/method may use an **expression body** `fn f(…): T => expr;` where `=> expr` is the implicit return; OR a **block body** `{ … }` which **always requires an explicit `return`**. Rationale: `=>` keeps one consistent "evaluates to / returns this expression" meaning across expression-bodied members, `match` arms, and the deferred lambdas — the intuition from C#'s `public string F(...) => …;`. - **Decided — how a `{ }` match arm produces a value: the `give` keyword** (DONE + verified). The arm forms: (1) `=> expr` implicit yield; (2) `=> { stmts; }` side-effect arm yielding **unit**; (3) `=> { stmts; give X; }` where **`give X` produces the enclosing block/arm's value** (execution continues after the match). Grammar: `GIVE: 'give'`; `give_statement : GIVE expression SEMI` (in `statement`). Works in **both** assignment (`const r = match { … give X … }`) and return position — tested `give.ex`; `http-endpoint.ex` `SystemFailure` arm uses it.
  - **The core model — EXIT vs PRODUCE are different operations, so they get different keywords:** `return` / `?` / `panic` all **exit the FUNCTION** (control leaves; `?` propagates `Err`/`None` to the caller, `panic` unwinds to a `try`/`catch`); `give` **produces** the enclosing match-arm's value (control continues). This is why `give` is NOT `return` (return = exit trap), NOT `yield` (reserved for future iterators), NOT `break` (reserved for loops), NOT `exit` (exit-connotation → misleads toward leaving the function).
  - **Why `?` propagates to the FUNCTION, not the match:** making `match` a `?`-boundary would silently retype the whole match to `Result<T,E>` the moment any one arm uses `?` — every *sibling* arm would then have to be `Result`-typed (or be magically `Ok`-wrapped). That non-local type contamination is the confusion. `?` on the whole match (`match value { … }?`) is fine and already parses — that's just postfix `?` on the match's own value. A *scoped* propagation boundary is a separate opt-in **`try { }` expression** (see deferred), NOT baked into `match`.

Only meaningful on *mutable* entities, not immutable value objects (those use `with`); overlaps with builders/object-initializers. A trait impl is a **global fact** about the type, not a local choice; making it local = manually threading a vtable through every generic instantiation = reinventing "pass an object," not a trait. (Haskell/Rust enforce global coherence for this reason; Scala's scoped `given`s allow local instances and are a known footgun.) Same coherence machinery as user-defined conversions (§4).

(B) *One type impls MULTIPLE different traits sharing a method name* → **qualify**. Common form: `IFoo::method(receiver)` (UFCS by trait). Two explicit forms use **parentheses, NOT angle brackets** (Kayden: `<…>` reads as generics — avoid it): (b1) value-cast-then-call, most C#-like (`((IFoo)x).M()`) → **`(value as IFoo).method(args)`** — `.` = instance call, dynamic dispatch through IFoo; (b2) type-qualified static reference → **`(Type as IFoo)::method`** — `::` = the method itself (rare, only when `IFoo::method` is still ambiguous). `.` (value/instance) vs `::` (type/static) distinguishes them. NB: `as` here is a non-lossy **interface upcast** (always valid if the type implements IFoo), distinct from `x as int32` value *conversion*; reusing `as` is fine. C#'s explicit interface implementation (`void IFoo.Test`) maps to (B): distinct-per-interface is **automatic** (separate `impl` blocks, no special syntax); `IFoo.Test` → `(Type as IFoo)::Test`; and "hidden from the inherent surface" comes **free** — trait methods are trait-scoped (need the trait in scope) while inherent methods (class body) are the type's own API.
  - **Capabilities are interfaces, NOT a universal base class.** `ToString`/`Display`, `Equatable` (backs `==`), `Comparable` (backs `<`), `Hashable`, `Try` (backs `?`), `Default` — all opt-in interfaces. **Primitives implement them too** — `char` (a lowercase `i32` scalar) gains these by implementing the interfaces, staying primitive (Rust: primitives `impl` traits). No `System.Object` base, no boxing, no forced runtime reflection. **Blanket impls** supported (`impl<T: Display> ToString for T`).
  - **Operators are trait methods** — no separate operator-overloading feature; an operator is sugar for a trait call. `a + b` → `Add::add(a, b)`; mapping `+`→`Add`, `-`→`Sub`, `*`→`Mul`, `/`→`Div`, `%`→`Rem`, unary `-`→`Neg`, `[]`→`Index`, `==`→`Equatable`, `<`→`Comparable`. **Associated `Output` type** lets the result differ from operands (`impl Mul<Vector2> for Vector2` can yield `double` for a dot product). **RHS is a trait parameter** — `impl Mul<double> for Vector2` (scalar) vs `impl Mul<Vector2> for Vector2` (vector) are separate impls ("define what the op means in this context"). Subject to the orphan rule (impl for a type you own), generic bounds, and blanket impls. **`+=` derives from `+` by default** (C# model: `a += b` ≡ `a = a + b`) — fits immutable value objects ("to change, make a new one"); a separate assign-trait (Rust `AddAssign`, in-place mutation) is optional-later for mutable entities. **NOT overloadable:** `&&`/`||` (preserve short-circuit — cf. C#'s `true`/`false` + `&`/`|`) and `=`. This is where C# is converging (C# 11 generic-math static-abstract-interface operators, `IAdditionOperators<…>`); Exodia gets it unified from the start. Prime use: value objects (`Vector2`, `Money`, `Complex`, matrices).
  - **DI (see §9).** Many DIFFERENT types each impl one interface ONCE — this is the **normal, intended** use, NOT the orphan problem (which is one type with two impls of the *same* interface). Services depend on the interface via **constructor injection** (interface-typed field ⇒ dynamic dispatch); a **composition root** selects the concrete impl at **runtime** from config (`match config.Provider { "aws" => new AwsBlobStorage(...), … }`) — full runtime swappability. **Compile-time DI** = the wiring graph is verified + generated at *compile* time (all deps satisfiable, reflection-free) — it does NOT freeze the provider choice. Avoids C#'s runtime-container failure (a missing registration exploding at runtime). Sketched: `IBlobStorage` (AWS/GCP/Azure impls) injected into `ImageService(storage: IBlobStorage, log: ILogger)`.
  - **Keyword: `interface`** (DECIDED — Kayden's usage throughout; also likes `contract`, changeable later; NOT `trait`, despite the Rust-style semantics). Tokens `INTERFACE: 'interface'`, `IMPL: 'impl'`; `for` reuses the existing `FOR`.
  - **Deferred — default methods** (interface methods with bodies). Part of the trait model (Rust traits have them), so planned, not merely optional. **Motivation:** primarily **API evolution / versioning** — add a member to an interface without breaking existing implementers (works even with zero interop); secondarily **interop** with ecosystems that have the feature — Java/Android (Java 8 default methods) and Swift/Obj-C protocols (this is why C# 8 added them; NB it was Java+Swift, *not* JS — JS has no interfaces). Interop is far out (no codegen/ABI yet; C-ABI interop wouldn't need it). **Private interface members:** C#'s exist only as *helpers for default methods* — private to the interface body, NOT a guarantee imposed on implementers (a private member can't be part of a contract). So they're meaningless until default methods exist. When default methods land, choose C#-style private interface members vs **Rust-style** (default methods call other trait methods; truly-private helpers are module-private free functions / a helper interface) — **lean Rust-style** (one fewer visibility rule, fits impl-blocks-+-free-functions grain).
  - **OPEN knobs:**  (b) interface-typed value auto-dynamic (C#/Java) vs explicit `dyn IFoo` (Rust) — auto reads naturally since `class` is already heap/reference; (c) orphan-rule strictness + newtype ergonomics; (d) associated types (Rust `trait Iterator { type Item; }`) vs generic-interfaces-only; (e) grammar for `impl` blocks, the `(Type as IFoo)::method` / `(value as IFoo).method()` qualified forms (parens, not `<>`), and `<T: IFoo>` generic bounds (bounds keep `<>` — they *are* generics).
- **Deferred/Open — `union` type (closed union of existing types).** Kayden wants to explore later; NOT needed now. It's the closed/exposed/explicit **dual to interfaces** (the *expression problem*: interfaces = subtype polymorphism = **open + encapsulated + implicit dispatch**; `union`/sum types = **closed + exposed + explicit dispatch**). Syntax sketch `union Pet(Cat, Dog, Fish);` — a closed list of member *types*. Defining properties: **implicit, non-intrusive membership** — a `Cat` is usable anywhere a `Pet` is required with **no wrapping**, and `Cat` needn't declare membership (the *union* lists it, so you can union types you don't own; a type can be in several unions — the TypeScript-union model, unlike Kotlin sealed which is *intrusive*); **explicit dispatch** — a union value exposes nothing callable directly (no auto vtable dispatch — that's the interface's job); to act you **must `match` on the type**. Differs from `enum` (which *wraps* `Pet::Cat(cat)` and matches *variant names*): a `union` has implicit membership and matches on the **type**. Build needs (future increment): `union_declaration` (`UNION identifier '(' type (',' type)* ')' SEMI`), implicit-membership coercion (semantic), **type patterns in `match`** (NEW pattern kind — `c: Cat =>` bind-name-`:`-type, a type test; current patterns are variant/literal/range/`_`), and exhaustiveness over the closed set. **Repr:** a tagged union (discriminant = which member type); "match on type" reads the tag (integer compare — **no runtime reflection**, AOT-friendly). Rationale: offer interface / union / enum side-by-side so the programmer picks the tool — interface (open, implicit), union (closed, explicit, non-intrusive membership), enum (closed, explicit, new data-carrying variants).
- Attributes/metadata system (DI, lifetimes).
- Bitwise family (`&`/`|`/`^`/`~`; shift syntax already decided as symbolic).
- `with` expression + compiler-generated value equality/copy for value objects.
- Nested types; `partial` methods; asymmetric `private(set)` visibility; per-binding deep immutability.

## 16. AST / Compiler Pipeline
- **Decided (2026-07-24) — introduce a real AST, moving off CST-driven codegen.** The CST codegen (`CodeGenVisitor`) had become a symbol-table + name-resolver + type-mapper + emitter at once (the five `_structs`/`_functions`/`_methods`/`_constructors`/`_symbols` registries are a bolted-on symbol table). The deferred semantic backlog (type errors, overload resolution, `const` enforcement, definite assignment, mixed-type checks) and the upcoming **interfaces** phase need a home for semantic info that the read-only ANTLR parse tree (CST) can't hold. Interfaces especially are semantic-heavy (impl resolution → static dispatch; vtables → `dyn`) and would otherwise pile more ad-hoc logic into codegen.
- **Design (validated by a working skeleton):**
  - **Insulation-first, grows into semantics** — the AST decouples codegen from ANTLR now; semantic annotations (resolved types/callables) are an *additive* later step (the `TextSpan` slot + immutable nodes are shaped so this doesn't require a reshape). Chosen over "semantic-home first" (bigger bite) or "insulation only" (reshape later).
  - **Visitor pattern over immutable nodes** — the OO/C# canonical (Roslyn's `SyntaxVisitor`, Clang's `RecursiveASTVisitor`, Crafting Interpreters all use it). Chosen over records+pattern-matching (rustc-style) because a compiler adds **passes** far more than node types, which is the Visitor's sweet spot (Expression Problem). Nodes are immutable records: base `AstNode(TextSpan)` implementing `INode`, with `T Accept<T>(IAstVisitor<T>)`; concrete nodes override `Accept`, abstract `Statement`/`Expr` don't.
  - **`TextSpan(int Start, int Length)`** — source span (offset+length) on every node, named `TextSpan` (Roslyn's name) to avoid `System.Span<T>` confusion. This is the LSP-insurance: analysis→text mapping falls out; retrofitting spans later is pervasive.
  - **Types are a SEPARATE sort** — `TypeRef`/`NamedType` hierarchy, NOT `INode`, NOT in `IAstVisitor<T>` (a type doesn't produce a value → would be a category error). Codegen *resolves* them via `ExodiaHelpers.MapPrimitiveType(string)` (a string overload added so the AST never touches `TypeContext`), not via `Accept`. This is the first of the AST "sorts" (terms / types / later patterns).
  - **Pipeline:** `source → ANTLR CST → AstLowering → AstVisitor (IAstVisitor<LLVMValueRef>) → IR`. **`AstLowering` is the ONLY class that touches `…Context` types** — the insulation seam. Structural nodes lower via typed hand-written methods; **expressions** lower via a small `ExodiaBaseVisitor<Expr>` sub-visitor (`ExpressionLowering`) that rides ANTLR's default `VisitChildren` passthrough down the precedence chain, so only leaves/operators need overrides.
  - **No red-green trees** — Roslyn's immutable+incremental-reparse optimization is an IDE feature (per-keystroke reparse with structural sharing); a batch compiler doesn't need it. A future language server *could* want it, but the switch stays cheap because (1) the AST is decoupled from ANTLR — only the lowering-input changes — and (2) every node carries a span. An LSP can also start with whole-file reparse (no red-green) first.
  - **Migration — parallel + golden-master.** `AstVisitor` is built alongside the intact CST `CodeGenVisitor`; `Program.cs` is swapped via comments (AST active, CST commented as reference). The existing 13-test suite's known outputs are the oracle: widen AST coverage construct-by-construct, expecting the same numbers, until the AST path matches on all tests — then retire `CodeGenVisitor`.
- **Status — widening toward CST parity (verified against the CST oracle at each step).** Covered on the AST path: functions + params + **calls** (two-pass declaration → forward refs + recursion; `CallableKey("", name, arity)` registry, overloading-ready), `return` (`Expr?`), int/float literals (unsuffixed), `BinaryExpr` (arithmetic `+ - * /` **and** comparisons unified in one node, int/float dispatch on `TypeOf`), `as` casts (`CastExpr` + four-quadrant `EmitCast`), `if`/`else` (basic blocks), `const`/`mut` locals + name references + assignment (symbol table = reused `Symbol` record; `ResolveLValue` for stores). Tests `ast-{skeleton,arith,cast,fptosi,if,if2,vars,assign,call}.ex` all match the CST oracle (e.g. `factorial(5)=120`). Design notes proven in practice: `AstLowering` is the sole ANTLR-touching class; `ExpressionLowering : ExodiaBaseVisitor<Expr>` rides ANTLR passthrough down the precedence chain; `TypeRef` resolved (not visited) via `MapPrimitiveType(string)`.
- **CST PARITY ACHIEVED (2026-07-24).** The AST path now covers everything the CST codegen did, verified by 15 `ast-*.ex` tests (PASS=15). Added since the last note: unary (`-`/`!`), short-circuit `&&`/`||` (phi, reusing `BinaryExpr`), `while`, bool literals, literal suffixes (type carried as a `TypeRef?` on `IntLiteral`/`FloatLiteral`), `print` (libc `printf`), parenthesized expressions, and **structs** — type registration (3-phase `VisitProgram`: structs → fn signatures → bodies), fields, `new` (positional + ctors), overloaded + named ctors (`CallableKey`), methods with `this` (by-pointer receiver), field read/write (GEP), `ResolveType` resolving struct names, and `=> expr` bodies **desugared to `{ return expr; }` at lowering** (cleaner than the CST's `VisitFunction_body`). **AST is now slightly ahead of CST:** a `VisitFnDeclaration` terminator-guard caps a fall-off block with `unreachable`, fixing the empty-merge edge case (`if` where both arms return) that the CST still defers (§14). `Program.cs` runs the AST path; the CST `CodeGenVisitor` has been **retired (deleted)**, and `ExodiaHelpers` trimmed to `CollectArgs` + `IsFloat` — the codebase is now cleanly AST-only.
- **Notable AST-vs-CST differences (settled in practice):** (1) every feature splits into a lowering arm (CST→AST node) + a codegen arm (AST→IR) vs the CST's fused visitor; (2) `BinaryExpr` unifies arithmetic + comparison + logical into one node (three CST visitors → one node + op dispatch); (3) `TypeRef` is a separate sort — resolved, never visited; (4) literals carry a `TypeRef?` for suffixes instead of baking the LLVM type inline (a first taste of node-attached semantic data); (5) `=> expr` desugars at lowering. Shared gotchas (not differences): parenthesized-expression handling and the if/loop terminator-guard, both needed the same treatment as the CST.
- **Next:** semantic passes (name resolution, type checking, …) remain the deferred backlog's home. **Now building interfaces**, scoped in two increments (generics/generic-bound dispatch deferred — needs a separate generics feature):
  - **Increment A — `impl` blocks + concrete static dispatch (2026-07-24).** Interface *declaration* emits no IR (a contract; "does T satisfy I" is a deferred semantic check). An `impl I for T { … }` just **adds methods to T** — impl methods register into `_methods` keyed `(TargetType, name, arity)` via the existing `DeclareMethod`/`EmitMethod`, so `t.method()` resolves through the unchanged `VisitMethodCall`. New AST data nodes: `MethodSignature`, `InterfaceDeclaration` (captured in `_interfaces` for B; no IR), `ImplDeclaration`; `ProgramNode` gains `Interfaces`/`Impls`. Phased `VisitProgram` extended: structs+interfaces → impl-method decls → fn sigs → bodies (fn, struct, impl). Deferred: interface-satisfaction check, `impl` for non-struct types, impl associated types/generic methods, and the `impl_outputs`-shifts-`type()`-indices case (increment A assumes no outputs, so `type(0)`=interface, `type(1)`=target).
  - **Increment B — `dyn` + vtables (DONE 2026-07-25).** Verified by `ast-dyn.ex` (Circle→75 / Square→16 through one call site). Pieces: **vtable** = `@T.I.vtable = constant [N x ptr]` per `(type,interface)`, slots in *interface* method order (so slot k means the same method for every impl), built in phase 1d (`EmitVTable`, after impl methods are declared, **before** function bodies since upcasts read `_vtables`); **`dyn I` type** = named `%dyn.I = {ptr, ptr}` (`DynType` AST node; `GetDynType` cached; `.StructName` recovers the interface); **upcast** (`x as dyn I`) = two `insertvalue`s building `{ &x (address, not load), @T.I.vtable }`; **dynamic dispatch** = `VisitMethodCall` detects a `dyn.`-prefixed receiver type → `EmitDynCall`: GEP/load the vtable + data ptr out of the fat pointer, GEP the interface-order slot, load the fn ptr, rebuild the callee signature from the interface `MethodSignature`, and indirect `BuildCall2` with the data ptr as `this`. **Deferred:** interface-satisfaction check (a missing method is a raw `KeyNotFoundException` at vtable build), supertraits at codegen, `dyn I[]` collections, associated types on impls, and generic-bound *static* dispatch (needs generics — a separate feature).

- **Generics — monomorphization at codegen (§189: zero-cost, AOT/LLVM). "rust/C# way": check-generic-once-with-bounds then substitute — but the bounds *check* needs the deferred semantic pass, so codegen does substitute-only for now (bounds parsed, NOT enforced; a concrete instantiation resolves methods on the concrete type directly).** Substitution = **environment**, not AST cloning (rustc keeps one generic body + substitutes during lowering; C++ clones-per-instance). One ambient field `_activeSubstitutionEnv : Dictionary<string, LLVMTypeRef>` (name→concrete LLVM type) that `ResolveType` consults *first* (`NamedType n when env.TryGetValue → bound`); empty during all non-generic codegen (zero impact). It's a field not a param because `ResolveType` is reached through the fixed `Accept<T>` visitor recursion — same ambient-state pattern as `_builder`/`_symbols`, and saved/restored the same way. AST: `TypeParam(Name, Bounds)` on all 6 generic-decl sites (inline `<T: I>` + `where T: I` both merged by `LowerTypeParams` into `Bounds`); `GenericType(Name, TypeArgs)` TypeRef for explicit `Box<int32>` in type positions (`LowerType` stopped discarding the grammar's `type_arguments`).
  - **Increment 1 — generic functions (DONE 2026-07-25).** Verified `ast-generic-fn.ex` (id(42)→42, dedup, pick$2$i32$double). Generic fns can't be emitted (no LLVM type for `T` → `ResolveType` throws), so **parked** in `_fnTemplates` keyed `(name, arity)` (arity ⇒ overloading); phases 2/3a only run over `concreteFns`. `VisitCall` forks: concrete (`_functions`) wins, else template → `InferTypeArgs` (match each param written as a bare `T` against the argument's `.TypeOf`; return-position-only `T` is uninferable → clear error) → `Instantiate`. `Instantiate` mangles a **globally-unique** name `id$1$i32` (name + **arity** + type-arg LLVM spellings — arity is essential or same-name/different-arity overloads collide), which is *both* the LLVM symbol *and* the `_instances` cache key (one identity, can't disagree); shallow-specializes `template with { Name = mangled, TypeParams = [] }` → runs the **normal** `DeclareFunction`/`VisitFnDeclaration` under the env. Instantiation happens **mid-emission of the caller**, so it saves/restores builder `InsertBlock` + `_symbols` + env (the shared builder cursor has no push/pop); caches **before** emitting the body so self-recursive generics terminate. int32/uint32 share an instance (both `i32`) — no signedness in the type system yet. Type-arg spellings in mangles go through `MangleType` (2026-07-25): struct args use `.StructName` (`describe$1$Circle`, `Box$Circle`) since `LLVMTypeRef.ToString()` on a struct returns the whole `%Circle = type {…}` definition; primitives keep `i32`/`double`.
  - **Increment 2 — generic structs (DONE 2026-07-25).** Verified `ast-generic-struct.ex` (inferred `new Box(7)`→Box$i32, explicit `new Box<double>(2.5)`, multi-param Pair$i32$double, nested Wrapper{Box<T>} via structural inference). A generic struct has **no layout until T is known** (`Box<int32>`/`Box<double>` are *different* LLVM types), so parked in `_structTemplates`; concrete-only in phases 1/3b. Key reuse: everything already dispatches on `structType.StructName`, so an instantiation is just an ordinary entry in the existing `_structs`/`_constructors`/`_methods` under the **mangled name `Box$i32`** — `StructInfo` shape unchanged. **Declaration/emission split** (the important design point): `InstantiateStruct` only *declares* (named type + field layout + ctor/method **signatures**) — builder-free, safe to call from any phase incl. while resolving another type; bodies are queued in `_pendingStructBodies` and emitted by `DrainStructBodies` (phase 3d) after fn bodies (LLVM allows calling a declared-not-yet-defined fn, so call sites only need the signature). Triggers: `new Box<int32>(...)` (`VisitNew` → `BuildStructEnv`) and explicit `Box<int32>` type positions (`ResolveType`→`ResolveGenericType`→`InstantiateStruct`). **`new` of a generic type REQUIRES explicit `<...>` (decided 2026-07-25) — no constructor-argument inference**, matching C# (which infers type args for *calls* but never for `new` of a generic type; deducing a container's element type from a ctor arg is C++ CTAD, the odd one out). This also avoids the trap where inferred struct-`T` + inferred method-`U` silently produce mixed-type bodies (`this.v * other` = `i32 * double`); that malformed-arithmetic case is a *separate* semantic-pass gap (binary ops don't type-check/coerce operands) and is NOT what the explicit-`new` rule fixes. `InferStructTypeArgs` removed. **Grammar edit** (regenerated parser, ANTLR 4.13.2): `new_expression` gained `type_arguments?` (`NEW qualified_name type_arguments? ('.' identifier)? arguments`) so `new Box<int32>(...)` parses. **Structural inference** (`Unify` + `_structInstances` reverse map mangled-name→template+env) survives only for generic *method/function* params (`fn f<T>(b: Box<T>)`), not `new`. **Deferred:** generic-struct *arity* overloading (`Box<T>` vs `Box<T,U>` — name-keyed for now); self-referential generic structs (`RegisterStruct` caches at end → would recurse); the 3-element postfix chain `w.inner.get()` (pre-existing `ExpressionLowering` limit, not generics); bound *enforcement* (semantic pass).
  - **Increment 3 — generic methods (DONE 2026-07-25).** Verified `ast-generic-method.ex` (`Wrap.echo<U>` on a plain struct → 7; `Box<T>.pickFirst<U>` → `Box$i32.pickFirst$double`/`$i32`, struct-T + method-U composed → 11). Mirrors the function machinery on the method path. **Env composition** is the point: a generic method (`method.TypeParams > 0`) is parked in `_methodTemplates` keyed `(owner, name, arity)` **capturing the owner's substitution env at park time** (`{}` for a plain struct, `{T->i32}` for Box$i32 — captured because parking happens inside `RegisterStruct`, which runs under the struct's env during `InstantiateStruct`). `DeclareOrParkMethod` parks-or-declares in `RegisterStruct`+`DeclareImpl`; `EmitStructBodies`/`EmitImpl` skip generic methods (emitted at call time). `VisitMethodCall` forks: `_methods` (concrete/already-instantiated) wins, else `_methodTemplates` → `InferMethodTypeArgs` (over the method's params, not the receiver; reuses `Unify`) → `InstantiateMethod`. `InstantiateMethod` **merges structEnv + methodEnv** (`{T->i32, U->double}`, method wins on clash), mangles `owner.name$typeargs.arity` (`Box$i32.pickFirst$double.1`), and reuses the *normal* `DeclareMethod`/`EmitMethod` (concrete = `template with { Name = mangled, TypeParams = [] }`) under the composed env — with the same mid-emission builder/`_symbols`/env save-restore and cache-before-body (recursive/mutually-recursive generic methods resolve via `_methods`). **Lowering fix folded in:** `LowerStruct` had been passing the *struct's* `type_parameters()` to each method (so `<U>` was silently dropped, methods inherited the struct's `<T>`); routed through `LowerMethodDeclaration` (reads `m.type_parameters()`) — the DRY fix. **Deferred:** generic methods on generic *impl* blocks (`impl<T> I for Box<T>` — impl type params not yet a thing); explicit method type-args `x.echo::<int32>(...)` (no grammar for it — inference only); bound *enforcement* (semantic pass).

## 17. Memory Management (automatic, no GC)
- **Decided (2026-07-24) — automatic, GC-free memory via reference counting; resource cleanup stays explicit.** Resolves §7's deferred "where class memory-management complexity lives" and confirms §5's `using` preference (now compiler-enforced). Two concerns are deliberately **separated**: *memory* (freeing the allocation — no observable effect, so automatic + invisible is fine) vs *resources* (IO side effects like closing a socket/file — must be visible, never magic). Goal that gates the whole design: **the developer does NOT manage lifetimes**; the default tier costs zero annotations, and Rust's lifetime-annotation model is explicitly rejected as un-intuitive.
- **Decided — three tiers, keyed off the existing `struct`/`class` split:**
  1. **`struct` = value object** (unchanged, §7): copied, stack, no heap. Data-race-free by independence. **No destructor** (a copied value with cleanup is a double-free footgun — cf. Swift: only classes get `deinit`).
  2. **`class` = managed reference (default):** heap, **reference-counted**, shared freely (ordinary reference semantics, C#/Swift-familiar — `const b = a;` aliases, refcount++). Memory freed automatically when the last reference drops. The RC *is* the meaning of `class` — automatic but not magic, because the keyword marks it.
  3. **`unique class` = owned/moved (opt-in):** heap, no refcount, single owner; assignment moves, lending uses access conventions (`inout`/`borrow`/`sink`). Zero-cost + data-race-free (exclusivity). For hot paths / owned buffers; **NOT** for shared services.
- **Decided — resource cleanup is an interface, not a keyword.** Rejected the `dtor`/destructor-keyword sketch (it hid IO behind an invisible automatic call). Cleanup = `impl Disposable for T` (a capability interface, consistent with §15 "capabilities are interfaces, not a base class") with a `Dispose(): void` method — the IO lives in plain, greppable sight. Naming: **`Disposable`/`Dispose`** (chosen; pairs with `using`) over `Destructor`/Rust `Drop`.
- **Decided — automatic cleanup is always marked + compiler-enforced.** A `Disposable` value's `Dispose()` runs **only** via `using` (the visible use-site marker: `using const conn = new Connection(...)` → disposed at scope end). A `Disposable` value NOT bound with `using` (nor moved/returned/explicitly disposed) is a **compile error** (must-use-style) — so resource IO can never happen on a silent drop. Preserves §5's explicit-`using` preference and adds enforcement.
- **Decided — `weak` for cycles.** RC leaks reference cycles; a `weak` reference marker (`parent: weak Option<Node>`) breaks them without keeping the referent alive (Swift/ObjC precedent). A cycle-collector backstop (cf. Nim ORC) is a possible later option (Open).
- **Decided — DI service lifetimes = who owns the reference (§9).** Services are default-tier `class` (shared → RC), injected as `dyn IInterface` (§15). **Singleton** = container/root holds one strong ref for the app lifetime (disposed at shutdown if Disposable). **Transient** = `new` per resolve, owned by the consumer, RC-freed when it is. **Scoped** = owned by a `using` scope, disposed at scope end (a DI scope and a `using` block are the same object). Registration expresses the lifetime in the composition root; unregistered `dyn` dep = compile error (§9 compile-time DI, reflection-free).
- **Open — shared services / thread-safety (KNOWN CONCERN).** A singleton shared across threads is shared mutable state — the one place "data-race-free by default" is NOT free. §6 immutability-by-default covers the common case: a service with no `mut` fields (stateless loggers/mappers/validators/most application services) is immutable → shareable → data-race-free with zero ceremony. Residual hard case = services with genuine shared *mutable* state (caches, pools, counters), which are hard in every language. Options to decide: (a) `actor`-style serialized access (Swift); (b) a `Mutex<T>`/`Synchronized<T>` library type (Rust `Arc<Mutex<T>>`); (c) a `Sendable`-style thread-safe marker the compiler requires on any cross-thread singleton. Lean: immutability-by-default handles most; design the mutable case with the concurrency tier.
- **Open — RC atomicity.** Cross-thread sharing (even of *immutable* data) mutates the refcount concurrently, so it needs atomic refcounts (safe, slower) vs non-atomic (fast, single-thread; the Rust `Rc`/`Arc` split). Lean **atomic-by-default** (uniform, one `class` concept, fits "no annotations to manage") + compiler elision/de-atomization when a refcount provably doesn't escape a thread (cf. Lobster compile-time RC elision, Swift ARC optimization) — push perf recovery into the compiler, not the syntax. Note: app-lifetime **singletons need no per-op RC** at all (held once by the root, freed at shutdown). Alternative: expose an `Rc`/`Arc`-style distinction (faster, costs a concept — fights intuitiveness). Undecided.
- **Open — access conventions for `unique class`** (`inout`/`borrow`/`sink` vs reusing `const`/`mut` + `consume`); the exclusivity check is **local per-call, NO lifetimes** (the anti-Rust requirement). Detail with the ownership tier.
- **Precedent:** Nim ARC/ORC (RC + move + deterministic destructors, no tracing GC), Swift (ARC default + opt-in `~Copyable`/`borrowing`/`consuming`; `deinit`; actors/`Sendable` for shared mutable), Vale (generational references — no-GC/no-borrow-check alternative, research-stage). Rust's borrow-checker-by-default explicitly NOT adopted (lifetime-annotation burden).

## 18. Enums & Pattern Matching
- **Model — Rust-style value-type sum types** (not C#). C#'s `enum` is just named integer constants (no payloads); C#'s de-facto sum type is a **sealed class hierarchy** (boxed; discriminant = runtime type/vtable). Exodia's `enum` is a **value type** with an explicit tag + inline payload (the Rust model). `Option`/`Result`/`Field` are ordinary library enums (§ intro) — no compiler magic.
- **Layout — option A, "wide struct" / sum-of-payloads (decided 2026-07-25).** An enum lowers to `{ i32 tag, ...payload slots for every variant }` — each variant gets its own non-overlapping slots; a value writes only the active variant's slots (others stay `undef`). `enum Result<T,E>{Ok(T),Err(E)}` → `{ i32, T, E }`. Chosen over **B (max-payload byte union, bitcast per variant)** and **C (boxed ptr)** because it needs **zero new infrastructure** — no target DataLayout (not wired yet), no bitcasts, no alignment math — and drops onto the generic-struct machinery verbatim. Cost: value size = **sum** of payloads, not max (wasteful for many-large-variant enums). Swappable to B later purely as a space optimization once a DataLayout exists (native codegen needs one anyway) — the representation is an internal detail behind `match`, so the language doesn't change. `Option<T>` is already optimal here (`None` has no payload → `{ i32, T }`).
- **Enum-ness is preserved for future metaprogramming.** Enums live in their **own `_enums`/`EnumInfo` registry, never `_structs`** — so the compiler never confuses an enum (tagged union) for a struct even though both lower to an LLVM struct. `EnumInfo(Type, Variants: name→EnumVariantInfo(Tag, Payload: StructInfoField[]))`. Runtime reflection (know-at-runtime it's an enum) = a future **metadata descriptor** pass keyed by type name; orthogonal to the value layout (identical work for A/B/C).
- **Increment — concrete enums: declare + construct + match (DONE 2026-07-25).** Verified `ast-enum.ex` (`IntOption::Some(42)`→42 with payload bind; `None`+`_`→7; `Shape::Rect(6,7)`→42 multi-payload; C-style `Color::Green`→2). Grammar already had everything (`enum_declaration`, `enum_variant(_payload)`, `match`, patterns) — pure lowering + codegen. **Construction** reuses existing lowering: `E::V(args)` parses as a call on the qualified name → `VisitCall` detects `::`, `TryResolveVariant`, `EmitEnumConstruct` (insertvalue tag@0 + payload slots); payload-less `E::V` parses as a `NameRef` → same construct with no args. **`match`** (`VisitMatch`): extractvalue the tag, then an **if-else chain** (not a `switch`, so guards/bindings compose uniformly later) — each arm tests its pattern (`TestPattern`: variant → `icmp` tag; wildcard/binding → always true), a matching arm binds payload (`BindPattern` extractvalue per slot into `_symbols`) and evaluates its body; arm values merge through a `phi`; the final fall-through is `unreachable` (**exhaustiveness assumed** — semantic-pass job). **Patterns:** `VariantPattern` (`Some(x)`, payload sub-patterns are bindings or `_`), `NamePattern` (bare name — variant-or-binding resolved at match time against `EnumInfo`), `WildcardPattern` (`_` — checked by text first since `_` also lexes as an identifier).
- **`match` increment 2 — guards + value bindings (DONE 2026-07-25).** **`when`-guards** (`Some(n) when n >= 10 => …`): the if-else chain (chosen over a `switch` for exactly this) restructured so a matched tag routes to an arm block that **binds the payload first, then evaluates the guard**, then conditional-branches to the body (true) or the next arm's test (false). A guard on the last arm failing → `unreachable` (non-exhaustive; semantic-pass job). **Value bindings** (`Red r`, `Some(x) s` — bind the whole matched value): grammar edit `primary_pattern : qualified_name pattern_payload? identifier?` (regenerated parser, ANTLR 4.13.2) — the trailing identifier binds the scrutinee; `VariantPattern` gained `string? Binding`, bound alongside any payload. Verified in `ast-enum.ex` (guard true→5, `Some(x) v`→bind both). **Still deferred:** generic enums (see below); literal/range patterns; or-patterns (`a | b`); block-arm bodies + `give`; nested variant patterns (`Some(Some(x))`); exhaustiveness checking.
- **Generic enums — `Option<T>`/`Result<T,E>` (DONE 2026-07-25).** Verified `ast-generic-enum.ex` (`Option<int32>::Some(7)`→7, `Option<double>::None`→8 distinct instance, target-typed `const c: Option<int32> = Option::Some(9)`→9 / `Option::None`→4, `Result<int32,int32>::Ok(42)`→42). Instantiation reuses the generic machinery — parked in `_enumTemplates`, `InstantiateEnum` mangles `Option$float` and `RegisterEnum`s the concrete copy under the env (no drain — enums have no bodies); `ResolveGenericType` handles enums so `Option<float>` resolves as a written type. **Two construction forms (decided 2026-07-25, both valid):** (A) **explicit** `Option<float>::Some(1.4f)` — new grammar rule `enum_construction : qualified_name type_arguments COLONCOLON identifier arguments?` (the required `type_arguments` disambiguate from a plain `Option::Some` call; placed first in `primary_expression`; ANTLR resolves the `<`-vs-less-than ambiguity by lookahead — verified `a < b` still parses as `icmp`); lowered to `EnumConstructExpr`. (C) **target-typed** `const x: Option<int32> = Option::Some(5)` / `Option::None` — the declared type drives it: `VisitVariableDeclaration` resolves the annotation FIRST (instantiating the enum), stashes it in `_expectedType`, and `TryConstructEnum` uses it to pick the instance (`_enumInstances` maps mangled→template to confirm the expected type is an instance of the named enum). No-context bare construction (`foo(Option::Some(5))`) errors with a message pointing to both forms — full target-typing across all positions is a semantic-pass job. **Still deferred:** literal/range patterns; or-patterns; block-arm bodies + `give`; nested variant patterns; exhaustiveness checking; generic-enum *methods* (enums have no methods yet).

## 19. FFI / extern
- **Goal-driven (2026-07-25):** the near-term milestone is a **minimal web API**. Its dependency chain is FFI → strings → memory/heap (§17) → collections → namespaces/imports → semantic pass → classes. Chosen first track: a **hello-HTTP proof-of-concept** to de-risk the toolchain before the big memory investment.
- **Boundary — thin C shim, not raw libc.** Raw sockets need `struct sockaddr`, pointers, and byte buffers, none of which the language has yet. So OS I/O hides behind a tiny C shim (`runtime/net.c`: `ex_listen`/`ex_accept`/`ex_send`/`ex_close`) taking only `int`/C-string. As the language grows real pointers/arrays/strings, functions **peel off the shim into pure Exodia** — the boundary shrinks, it doesn't move.
- **`extern fn` (DONE 2026-07-25).** Grammar: `accessability_modifier* EXTERN? FN … (function_body | SEMI)` — an extern is a signature terminated by `;` (no body). Codegen: `DeclareFunction` runs (phase 2) but phase 3a skips `IsExtern` — a declared-but-undefined function *is* an LLVM `declare`; the linker supplies it (`clang server.o runtime/net.c`). **Name/symbol split:** the node carries `Name` (how Exodia refers to it — namespace-scoped + mangled later) and `LinkName` (the raw C symbol, **never** mangled); `AddFunction(LinkName ?? Name)`, calls resolve by `Name`. The future namespace-mangler exempts externs and keeps `LinkName` — so an extern can live in a namespace under an arbitrary Exodia name while linking to a fixed C symbol (the `private extern fn ex_listen` + `public fn listen(p: Port)` wrapper pattern). Generic externs rejected (no single C symbol). Explicit `link_name`/`EntryPoint` syntax deferred (field exists; wrapper covers it for now).
- **`cstr` + string literals (DONE 2026-07-25).** `cstr` = `i8*` (a byte pointer — NOT the future `String` type). A string literal lowers to a private global byte array (escapes processed at lowering: `\n`/`\r`/`\t`/`\0`) and its value is a `cstr`. Enough to pass fixed text (HTTP responses) to C. Real `String` (owned, length-carrying, UTF-8) comes with the memory tier.
- **Variadic `...` (DONE 2026-07-25).** Grammar: trailing `(',' ELLIPSIS)?` on the parameter list (`ELLIPSIS: '...'`). Codegen: `LLVMTypeRef.CreateFunction(ret, params, IsVarArg: true)`; variadic fns are keyed by name in `_variadics` (call arity varies, so the arity-keyed `_functions` lookup can't find them). One `extern fn printf(fmt: cstr, ...): int32` handles every call shape, floats included (LLVM emits the correct x86-64 `al`-register variadic call — the fixed-arity workaround couldn't). **NB — C varargs are not arrays**; the C ABI passes them via the calling convention (`va_list`), so this is independent of the (separate) arrays feature.
- **Void-call naming bug (fixed 2026-07-25).** LLVM forbids naming a `void`-returning instruction; `BuildCall2(..., "call")` on a void fn (`ex_send`) errored. Fix: `EmitCall` names the result `""` when the signature returns void. Same latent bug still lurks in `VisitMethodCall`/`EmitDynCall` for void *methods* (not yet hit).
- **PoC milestone (DONE 2026-07-25).** `examples/http-server.ex` — an HTTP server in Exodia over the shim — builds (`exodia file.ex | llc | clang - runtime/net.c`) and answers `curl localhost:8080` with `Hello from Exodia`; the accept loop serves repeated requests. Proves the whole toolchain reaches the network. A compiler **driver** (auto `llc`+link) is deferred ergonomics.

## 20. Unit type (not void)
- **Decided (2026-07-25) — the "returns nothing" type is `Unit`, a first-class type, NOT C's `void`.** `void` is the *absence* of a type (can't be generic, stored, or composed); `Unit` is a real type with exactly **one value** (ML/Rust/Swift/Kotlin tradition). This fits Exodia's expression-oriented, generics-and-`match`-heavy design and is **load-bearing for the web API**: a fallible-but-empty result is `Result<Unit, ApiError>` (e.g. `DELETE /users/{id}`), which `void` literally cannot express. It also dissolves the "void call has no value" special case at the language level — every call yields a value (`unit` when there's nothing meaningful).
- **Keyword — `unit` (Kayden's call: a keyword, NOT `()`).** `unit` is the canonical type name and the value; `void` is kept as an accepted **type alias** for familiarity. (`()` rejected — reads as empty-tuple noise to Kayden.)
- **Lowering — `Unit` is zero-sized; it erases at the ABI.** *Return position:* a `unit`-returning function lowers to an LLVM `void` return (nothing to hand back), so extern C `void` functions and Exodia `unit` functions share one representation, and the `EmitCall` void-check stays as an **ABI-lowering detail**, not a language concept. *Value position* (a `unit` inside `Result<Unit, E>`): a zero-size representation — cleanest is to contribute **no payload slot** (Rust's ZST model), so `Ok(unit)` just sets the tag.
- **Increment 1 — return position (DONE 2026-07-25).** `unit`/`void` resolve to LLVM `void`; `fn f(): unit` works; `return;` and `return unit;` both emit `ret void`; a `unit`-returning function that falls off the end emits `ret void` (was `unreachable`). The `unit` value keyword lowers to a `UnitLiteral`.
- **Increment 2 — value position (deferred).** The zero-size representation so `Result<Unit, E>` / `Option<Unit>` and `const x: unit` work: `UnitLiteral` in a non-return position currently errors, pointing here. Lands when the first `Result<Unit, E>` needs it (alongside the memory/collections work).

## 21. Namespaces (codegen)
- **Approach (2026-07-25) — flatten-with-qualified-names at lowering.** `namespace Foo { … }` (grammar already present, previously not lowered) is flattened: each member's declared name is **prefixed to its qualified form** (`Foo::bar`, `Foo::Point`, nested `Foo::Bar::baz`) in `LowerNamespace`. Because a qualified *reference* already spells that prefix (`Foo::bar()`, `new Foo::Point`, `Foo::Sign::Pos`), **fully-qualified refs resolve for free** — no resolver changes; the qualified name IS the `_functions`/`_structs`/`_enums` key and the (quoted) LLVM symbol. Verified `namespace-codegen.ex` (qualified `new Math::Point`, `Math::quad`, namespaced enum `Math::Sign::Pos`, method `Math::Point.sum` → 29).
- **Unqualified sibling calls** resolve via an **enclosing-namespace fallback**: `VisitCall`, on an exact-key miss, retries `NamespaceOf(currentFn)::callee` (current fn derived from `_builder.InsertBlock.Parent.Name` — no threaded state). `TryConstructEnum` splits on the LAST `::` so namespaced enums (`Math::Sign::Pos`) construct.
- **Externs keep their raw C symbol** — a namespaced `extern fn` gets its Exodia `Name` prefixed but `LinkName` stays the unmangled C symbol (the §19 decoupling), so it still links.
- **Deferred to the semantic pass:** `import`/`using`, cross-namespace *unqualified* resolution, unqualified sibling *types* (sibling type refs must be written qualified for now — only sibling *calls* get the fallback), ambiguity/collision checks, and classes-in-namespaces (classes not built). Impls/interfaces in a namespace are optimistically same-namespace-qualified (correct when trait+type+impl are colocated).
